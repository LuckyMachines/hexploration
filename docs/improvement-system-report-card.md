# Improvement System Report Card

## v0.1.0 - Baseline audit

The repository already had unusually capable specialist loops, but they behaved like excellent instruments without a shared dashboard. Evidence was abundant; portfolio-level prioritization and real-player closure were not.

| Dimension | Baseline | Evidence | Gap to a stricter A |
| --- | --- | --- | --- |
| Evidence capture | A- | Simulator, Oracle, memory, verification, marketing, UI, and art reports | No common freshness or confidence contract |
| Reproducibility | A- | Deterministic scripts and local checks | No single changed-surface entry point |
| Automated verification | B+ | Broad tests and hard verification tiers | Promotion was not coupled to evidence state |
| Prioritization | B | Many useful next actions | No ranked portfolio action across disciplines |
| Cross-system coherence | C+ | Specialist tools reference some shared artifacts | Grades, owners, and readiness terms were inconsistent |
| Real-player validation | C | Strong automated proxies | No structured recent-session threshold or consent-safe ledger |
| Promotion discipline | B | Art review and release checks contain gates | No shared legal state machine or decision ledger |

Overall baseline: **B**. Confidence: **high** in the diagnosis, **medium** in product quality because current human observation evidence is absent.

## Stricter A bar

Every meaningful change begins with a falsifiable hypothesis and ends with automatically captured before/after evidence, an explicit decision, a legal promotion state, and one ranked next action. Required evidence must be current, verification must be proportional to the changed surface, and at least five recent representative human sessions must cover first and return play.

## v1.0.0 - Control-plane implementation

| Dimension | Regrade | What changed |

| Evidence capture | A | Shared evidence requirements, freshness, record thresholds, and compact/internal outputs |
| Reproducibility | A | One documented CLI, deterministic classification, scoped quick/full commands, tests |

Verified portfolio regrade: **B** overall with low confidence because representative human-play evidence is still empty. The improvement-system surface is **B+ with high confidence** after its unit suite and the cross-system smoke suite passed. The next regrade comes from generated portfolio evidence, not this document's assertion.

The first all-surface automated run recorded 100% scoped verification coverage, 0% regression rate, 86% required-evidence freshness, 88% implementation-checklist completion, one stale registered report, and zero human playtests. All selected automated checks passed. The low portfolio confidence is therefore localized to missing human observation rather than failing code.

## v1.1.0 - Bounded automatic repair

The default command now performs a diagnose-repair-verify-regrade loop instead of stopping at recommendations. Repair recipes are versioned, command-allowlisted, risk-bounded, write-path-declared, iteration-limited, non-repeating, and protected by a concurrent-run lock. Generated simulation, UI-density, marketing, SEO, and verification evidence can self-heal. Unsupported code changes, creative choices, and player observations are packaged for human or assisted work.

| Dimension | Regrade | Evidence |
| --- | --- | --- |
| Automatic remediation | A- | Bounded recipe selection, dry run, verification, and ineffectiveness detection |
| Change safety | A- | Declared write paths, dirty-file fingerprints, policy-violation stop, no automatic commit |
| Auditability | A | JSON and Markdown apply reports retain commands, outcomes, touched paths, and blockers |
| Human-truth protection | A | Human playtest deficits stop safely and cannot be filled by automation |

Improvement-system regrade: **A-**, pending repeated production use of successful repairs. Overall product portfolio remains **B** until observed-player evidence and the stale UX audit are resolved.
